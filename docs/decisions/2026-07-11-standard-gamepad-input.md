## 決策內容

產品輸入裝置定位由「真實 RC 遙控器（RadioMaster／FrSky USB，16 通道）」改為 **Xbox 360 相容的一般 USB／藍牙 game 手把**；移除 RadioProfile 與 16 通道需求，輸入 Profile 縮為 GamepadProfile + KeyboardProfile（鍵盤僅 fallback）。

## 驅動因素（維護者 2026-07-11 確認）

1. **環境限制**：維護者手邊沒有 RC 遙控器實機——RC 專屬驗收（16 通道校準、RadioMaster/FrSky 實機各一）在 Linux 實測主車道下永遠無法誠實取證。
2. **產品定位**：本產品的目標使用情境就是用標準手把遊玩；RC 遙控器定位屬過度工程，不對應實際使用者。

## 非門檻下修裁定（明文）

G0.5、G4B.UI2、G5.1、G5.2、G5.6 由「16 通道／RC 實機」判準改為「Xbox 360 相容手把」判準，屬**驗收裝置定義調整**，非門檻數值下修：

- 各 Gate 的**數值門檻不變**（校準時限、延遲 ms、顯示即時性等維持原值）。
- 變更的是「受測裝置類別」——與 2026-07-11 Linux 實測主車道（驗收平台範圍調整）同一性質，依 PRD 1.4 結構成立。
- RC 遙控器支援若未來出現真實需求（客戶指名＋取得實機），以新增 Profile 方式回補，不需修改既有門檻。

## 連動

- G5.4 端到端延遲門檻（桌面 ≤40ms）不變，量測對象改為標準手把鏈路。
- `docs/development-decision-flow.md` 應補本決策節點（驅動因素：環境限制＋產品定位）。
