# 手把校準驗收合約白話說明（G4B.UI2）

本文件解釋 #40（手把 Setup Flow）六項校準合約的意義，供實作與驗收對照。門檻數值出自 PRD G4B.UI2（v3.3 起受測裝置為 Xbox 360 相容標準手把，數值未變——見 `docs/decisions/2026-07-11-standard-gamepad-input.md`「裝置定義調整、非門檻下修」裁定）。

校準精靈結束前，系統必須能證明「這支手把堪用」。六關如下：

| 合約 | 白話 | 為什麼重要 |
|---|---|---|
| **唯一四軸** | roll／pitch／yaw／油門各自對到**不同的**實體搖桿軸，不能一軸兼兩職 | 若油門和 yaw 綁同一縱軸，推油門就會同時轉向——飛不了 |
| **端點 ≥95%** | 搖桿推到底時，讀值至少達滿刻度 95% | 老化或縮刻度的搖桿推到底只回報 80%，永遠打不出全速率，手感變鈍 |
| **中心 ±2%** | 放手後讀值回到中心 ±2% 以內 | 中心偏移＝沒碰搖桿也持續輸出微小指令，機體單邊漂移 |
| **1 秒 RMS ≤0.5%** | 手不碰、靜置 1 秒，訊號抖動（RMS）≤0.5% | 電位器雜訊會被 1kHz 飛控當成微操，機體無故抽動 |
| **Arm/Mode 不重複且去抖 ≤50 ms** | 解鎖鍵與模式鍵必須不同鍵；按一下只觸發一次，機械彈跳 50ms 內濾除 | Arm 是安全關鍵：彈跳「一按變兩按」會瞬間解鎖又上鎖或誤觸 |
| **油門低位** | 解鎖（arm）當下油門必須在最低位 | 真機經典安全互鎖：防止油門推一半解鎖瞬間暴衝 |

## 自動化驗證方式（可注入樣本）

測試不依賴實體手把：以程式注入合成搖桿訊號樣本——**好手把樣本**（六關全過）與**壞手把樣本**（中心偏移、雜訊超標、端點不足、按鍵彈跳、油門非低位、軸重複指派各一）——驗證每一關「該過的過、該擋的擋」（紅綠對照）。CI 據此自動回歸；維護者遊玩驗收只需確認真手把插上走完精靈的實際體驗（Linux 本機 headed，依 2026-07-11 裁定）。
