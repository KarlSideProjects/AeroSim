# G0.1 Harness Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate false G0.1 passes, make every report traceable to the measured binaries, accurately declare the measured aerodynamic workload, and automate a real-GPU 10+60 second reference run.

**Architecture:** The runner owns benchmark mode and eligibility, rebuilds the GDExtension, and passes immutable provenance into the Godot collector. The report builder calculates percentiles for all modes but only emits a gate verdict for an eligible, fixed-duration gate run. A separate scheduled workflow runs the full reference protocol on the self-hosted NVIDIA display and stores its artifacts locally.

**Tech Stack:** Bash, Python 3 standard library/unittest, Godot 4.7 GDScript, SCons, GitHub Actions.

## Global Constraints

- G0.1 gate protocol is exactly 10 seconds warmup plus 60 seconds measured at 240 Hz, Jolt, VSync off, P99 at most 3 ms.
- Short runs are smoke tests and must never be labelled as a G0.1 gate result.
- Ryzen 9 7945HX + RTX 4060 Ti results are reference-only while the repository PRD still freezes Ryzen 5 5600 + GTX 1660S.
- Reports must preserve raw samples, environment, source revision, Godot version/hash, godot-cpp revision, and GDExtension hash.
- The current single-aircraft workload only exercises A3 drag and A4 ground effect; it must not claim A5 downwash.
- No new third-party runtime or test dependency.
